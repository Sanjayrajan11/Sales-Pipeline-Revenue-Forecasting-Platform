# Hiring-manager review

## Assessment
This is a credible fresher-level BA/BI portfolio when the candidate can reproduce the run and explain its scope. It is not evidence of commercial impact or production deployment.

| Dimension | Assessment | Evidence and gap |
|---|---|---|
| Business relevance | Strong for fresher | Realistic management decisions; stakeholder requirements are simulated |
| Requirements | Solid | Explicit scope, stakeholders, acceptance criteria and process maps; no real elicitation |
| SQL depth | Strong for fresher | 42 meaningful queries and windows; no production warehouse optimization study |
| Python | Solid | Modular pipeline, tests, reproducibility; local memory use and single-user assumptions remain |
| Forecasting | Careful baseline work | Temporal reconstruction and held-out tests; only one-step evaluation, short calibration window |
| Dashboard | Broad functional coverage | Real filters/drill-down/scenarios; Streamlit limits full custom SaaS interaction design |
| UI identity | Distinct chosen direction | Black background, white text, grayscale charts and editorial briefing; prior payment project was not supplied for direct comparison |
| Data realism | Useful but bounded | Linked attributes, probabilistic stage loss, censored histories; immutable dates and simple stage progression |
| Testing | Good portfolio practice | Numeric, temporal, SQL and UI checks; not a production security/load/accessibility audit |
| Explainability | Strong if studied | Transparent policies and simple models; candidate must distinguish probability from policy score |
| Resume value | Credible | Executed technical outputs are measurable; no invented revenue recovery or real-company claims |

## Interview risks
Do not call synthetic requirements stakeholder interviews. Do not call booked multi-year contract value recognized annual revenue. Do not convert policy risk into a calibrated loss probability. Do not claim Power BI Desktop execution from the DAX guide. Do not describe an indicative range as guaranteed coverage. Do not claim reduced losses from hypothetical scenario output. Do not claim uniqueness relative to an unseen prior project.

## Improvements with highest value
1. Obtain a small anonymized CRM extract with historical revisions and validate the event model.
2. Agree metric ownership with sales and finance before adding features.
3. Add 3/6/12-month rolling tests and interval calibration with a longer real history.
4. Introduce reopening and date-slippage events, plus capacity-aware scenarios.
5. Evaluate an actual intervention prospectively and report uncertainty.

No numeric hiring score is assigned: it would imply more objectivity than a self-review can support. The strongest signal is whether the candidate can defend the data grain, denominators, period alignment and leakage safeguards without memorizing answers.
